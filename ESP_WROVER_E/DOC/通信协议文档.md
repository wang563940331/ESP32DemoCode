# MQTT / JSON 通信协议

> 依据当前固件实现（`components/APP/WIFI_STA/json.c`、`telemetry.c`、`mqtt.c`、`APP/OTA`）整理。
> 载荷为 **UTF-8 JSON**，字段名大小写敏感。
> 文档按**功能**组织：每个功能下列「平台/设备下发」与「应答/上报」。

---

## 1. 传输说明

| 项                   | 说明                                                             |
| -------------------- | ---------------------------------------------------------------- |
| 传输                 | MQTT                                                             |
| 上行主题（设备→云） | NVS `mqttpub`（网页 `/wsconfig` 可改）                       |
| 下行主题（云→设备） | NVS `mqttsub`（网页 `/wsconfig` 可改）                       |
| QoS                  | 订阅 QoS=1；发布按 MQTT 客户端配置                               |
| 周期上报             | 连接成功后约每 `MQTTUBLISHED`（默认 15s）上报一次 `MeterAll` |
| 设备标识             | 本机 SN（NVS `gate.sn`）；报文字段 **`device`**        |
| 时间基准             | **北京时间**（`TZ=CST-8`）；`time` / 历史电量时刻 / 日志时间均按东八区 |

### 下行处理流程

1. 解析 JSON
2. 若存在 `device`：须与本机 SN 一致，否则丢弃
3. 按 `Type` 查分发表；**缺少 `Type` 时默认按 `Control` 处理**
4. handler 成功且表项配置了 ack 时，自动回应对应应答包

---

## 2. 通用报文骨架

```json
{
  "Type": "XXX",
  "device": "设备SN",
  "params": {
    "...": "..."
  }
}
```

| 字段       | 必填     | 说明                                      |
| ---------- | -------- | ----------------------------------------- |
| `Type`   | 建议必填 | 消息类型；下行缺省时按 `Control`        |
| `device` | 建议必填 | 设备 SN；下行缺失时仍继续分发（仅打日志） |
| `params` | 视类型   | 业务参数对象                              |

---

## 3. 功能一览

| 功能         | 方向       | Type / 应答                                                                                                     |
| ------------ | ---------- | --------------------------------------------------------------------------------------------------------------- |
| 登录/状态    | 设备 → 云 | 上报 `StatusChange`（含 `version`）；无专用应答                                                             |
| 遥测快照     | 设备 → 云 | 周期上报 `MeterAll`；无应答                                                                                   |
| 远程控制     | 云 ↔ 设备 | 下发 `Control` → 应答 `Control_ACK`（`ack=ok`）；过程可再报 `StatusChange`                             |
| 召唤电量历史 | 云 ↔ 设备 | 下发 `GetData` → 应答 `GetData_ACK`（`ack=ok` + `DailyEnergy`）                                        |
| FTP 远程升级 | 云 ↔ 设备 | 下发 `FtpOTA` → 立即 `FtpOTA_ACK`；下载中 `FtpOTA_Status`（每 10%）；成功重启后再报登录 `StatusChange` |

明细见第 4 节。

---

## 4. 指令格式（按功能）

### 4.1 登录 / 状态

设备上线、状态变化时主动上报。平台**无专用登录应答**；靠后续业务交互或超时判断在线。

#### 4.1.1 登录 / 状态上报 — `StatusChange`（设备 → 云）

```json
{
  "Type": "StatusChange",
  "device": "CTR",
  "params": {
    "ctrlacl": "online",
    "version": "main-38e17e11",
    "buildtime": "2026-11-08 16:41:27",
    "time": "2026-11-08 21:16:37"
  }
}
```

| 字段                 | 说明 |
| -------------------- | ---- |
| `params.ctrlacl`   | 状态描述，如 `online`、`开机执行`、`开机完成` 等 |
| `params.version`   | 固件版本（`标签-短哈希`，如 `main-38e17e11`） |
| `params.buildtime` | 固件**编译时间**，格式同 `time`（构建机本地时，工程约定北京时间） |
| `params.time`      | 当前设备时间 `YYYY-MM-DD HH:MM:SS`（**北京时间**，`TZ=CST-8`） |

#### 4.1.2 登录应答

**无。** 平台不必回包。

---

### 4.2 遥测快照（电表 / 传感器）— `MeterAll`（设备 → 云）

设备周期主动上报；平台无需下发、**无应答**。

**数据格式说明：**

- 根对象固定：`Type` = `"MeterAll"`，`device` = 本机 SN，业务测点全部在 `params` 内。
- `params` 内测点值均为 **JSON 字符串**（不是 Number），例如 `"228.4"`。
- 无效/未就绪字段**整项省略**（不上报该 key）：温度约 -200、湿度 &lt; 0、电表瞬时量/峰值为 0。
- `time` 为本地时间字符串，格式 `YYYY-MM-DD HH:MM:SS`。

**完整示例：**

```json
{
  "Type": "MeterAll",
  "device": "CTR",
  "params": {
    "headid": "2",
    "temperature": "27.40",
    "humidity": "39.00",
    "VolageA": "228.4",
    "CurrentA": "1.012",
    "PowerPA": "174.6",
    "Frequency": "49.96",
    "Totol_Energy": "635.72",
    "time": "2026-09-02 22:35:52",
    "PowerPeak_3min": "185.5",
    "PowerPeak_1h": "214.3",
    "PowerPeak_1d": "214.3",
    "PowerPeak_7d": "374.9",
    "PowerPeak_1m": "386.0"
  }
}
```

**`params` 字段表：**

| 字段               | 类型   | 单位/含义 | 备注                                     |
| ------------------ | ------ | --------- | ---------------------------------------- |
| `headid`         | string | 上报序号  | 设备侧自增计数转字符串                   |
| `temperature`    | string | ℃        | 无效（约 -200）时省略                    |
| `humidity`       | string | %RH       | &lt;0 时省略                             |
| `VolageA`        | string | V         | A 相电压；0 时省略                       |
| `CurrentA`       | string | A         | A 相电流；0 时省略                       |
| `PowerPA`        | string | W         | 有功功率；0 时省略                       |
| `Frequency`      | string | Hz        | 电网频率；0 时省略                       |
| `Totol_Energy`   | string | kWh       | 累计电能（字段名沿用历史拼写）；0 时省略 |
| `time`           | string | 本地时间  | `YYYY-MM-DD HH:MM:SS`，一般总有        |
| `PowerPeak_3min` | string | W         | 约 3 分钟窗口峰值；0 时省略              |
| `PowerPeak_1h`   | string | W         | 约 1 小时窗口峰值；0 时省略              |
| `PowerPeak_1d`   | string | W         | 1 天窗口峰值；0 时省略                   |
| `PowerPeak_7d`   | string | W         | 7 天窗口峰值；0 时省略                   |
| `PowerPeak_1m`   | string | W         | 1 月窗口峰值；0 时省略                   |

### 4.3 远程控制

`open` / `close` 驱动 **PWM 舵机** 按电脑机箱电源键（不是继电器断电）。`reboot` 重启的是 **ESP32 本机**。

#### 4.3.1 平台下发远程控制 — `Control`（云 → 设备）

```json
{
  "Type": "Control",
  "device": "CTR",
  "params": {
    "cmd": "open"
  }
}
```

| `params.cmd` | 含义                  | 执行                                                                                  |
| -------------- | --------------------- | ------------------------------------------------------------------------------------- |
| `open`       | 电脑开机              | 舵机按下约 1s 后回位；过程可再上行 `StatusChange`（如 `开机执行` / `开机完成`） |
| `close`      | 电脑关机（松键/回位） | 舵机回到松开位                                                                        |
| `reboot`     | 远程复位本设备        | `esp_restart()`                                                                     |

#### 4.3.2 远程控制应答 — `Control_ACK`（设备 → 云）

`Control` 执行成功后回：

```json
{
  "Type": "Control_ACK",
  "device": "CTR",
  "params": {
    "ack": "ok"
  }
}
```

| 字段           | 说明                 |
| -------------- | -------------------- |
| `Type`       | 固定 `Control_ACK` |
| `params.ack` | 执行成功为 `"ok"`  |

---

### 4.4 召唤电量历史

#### 4.4.1 平台下发召唤 — `GetData`（云 → 设备）

```json
{
  "Type": "GetData",
  "device": "CTR",
  "params": {
    "get": "MeterHistory"
  }
}
```

| `params.get`   | 含义             |
| ---------------- | ---------------- |
| `MeterHistory` | 召唤区间电量历史 |

#### 4.4.2 召唤电量历史应答 — `GetData_ACK`（设备 → 云）

`GetData` 成功后回；历史在 `params.DailyEnergy`：

```json
{
  "Type": "GetData_ACK",
  "device": "CTR",
  "params": {
    "ack": "ok",
    "DailyEnergy": [
      {
        "date_1": "2026-09-01 00:00",
        "kWh": 1.234
      },
      {
        "date_2": "2026-09-02 00:00",
        "kWh": 0.856
      }
    ]
  }
}
```

| 字段            | 说明                                                  |
| --------------- | ----------------------------------------------------- |
| `Type`        | 固定 `GetData_ACK`                                  |
| `params.ack`  | 受理成功为 `"ok"`                                   |
| `DailyEnergy` | 区间用电数组，最多约 30 条（环形缓冲）                |
| `date_N`      | 该槽采样时刻 `YYYY-MM-DD HH:MM`（N 从 1 递增）      |
| `kWh`         | 该区间用电量（kWh，JSON **数值**，约 3 位小数） |

无历史时 `DailyEnergy` 可能缺失（空历史不追加该字段），`ack` 仍为 `"ok"`。

### 4.5 FTP 远程固件升级

云端下发 FTP 参数与固件名；设备**接受任务后立即**回 `FtpOTA_ACK`，下载过程中按 **每 10%** 上报 `FtpOTA_Status`，后台 FTP **边下边烧**，成功约 3s 后重启。重启后会再发 4.1 登录 `StatusChange`（含新 `version`）。

#### 4.5.1 平台下发升级 — `FtpOTA`（云 → 设备）

```json
{
  "Type": "FtpOTA",
  "device": "CTR",
  "params": {
    "IP": "*****",
    "PORT": "*****",
    "USER": "*****",
    "PASSWD": "*****",
    "PATH": "/ESP32OTA",
    "FILENAME": "NEW"
  }
}
```

也可指定确切文件：`"FILENAME": "RemoteControlOmain-ea386ac4.bin"`。

| 字段                | 必填 | 说明                                                                                                               |
| ------------------- | ---- | ------------------------------------------------------------------------------------------------------------------ |
| `params.IP`       | 是   | FTP 主机名或 IP；首尾空格自动去掉                                                                                  |
| `params.PORT`     | 是   | 端口，字符串或数字均可                                                                                             |
| `params.USER`     | 是   | 登录用户名                                                                                                         |
| `params.PASSWD`   | 是   | 登录密码                                                                                                           |
| `params.PATH`     | 是   | 远程目录，如 `/ESP32OTA`                                                                                         |
| `params.FILENAME` | 是   | 远程固件名：`RemoteControlO<版本>.bin`；或填 **`NEW`** 表示下载该目录内**修改时间最新**的 `.bin` |

#### 4.5.2 升级应答 — `FtpOTA_ACK`（设备 → 云）

接受任务成功后回：

```json
{
  "Type": "FtpOTA_ACK",
  "device": "CTR",
  "params": {
    "ack": "OK"
  }
}
```

| 字段           | 说明                |
| -------------- | ------------------- |
| `Type`       | 固定 `FtpOTA_ACK` |
| `params.ack` | 受理成功为 `"OK"` |

说明：

- 该应答仅表示**已启动 OTA 任务**，不是升级完成。
- 升级失败不重启；进行中再次下发会被拒绝（设备忙）。
- **仅 MQTT 下发**：不提供串口 `update`；公共仓库不硬编码 FTP 机密，须在报文中带齐 IP/PORT/USER/PASSWD/PATH/FILENAME。
- `FILENAME=NEW`：设备先 MLSD（失败则 NLST+MDTM）扫描 `PATH`，选最新修改时间的 `.bin` 再下载。
- 上传固件请手动执行 `./otapush.sh`（凭据用环境变量或本地 `.env`），把 bin 上传为 `RemoteControlO<版本>.bin`。

#### 4.5.3 升级进度 — `FtpOTA_Status`（设备 → 云）

下载过程中按进度门槛上报（**每 10% 一次**：10、20、…、100）：

```json
{
  "Type": "FtpOTA_Status",
  "device": "CTR",
  "params": {
    "status": "download",
    "progress": "50"
  }
}
```

| 字段                | 说明                                                           |
| ------------------- | -------------------------------------------------------------- |
| `Type`            | 固定 `FtpOTA_Status`                                         |
| `params.status`   | 当前阶段，下载中为 `"download"`                              |
| `params.progress` | 进度百分比**字符串**，如 `"10"` / `"50"` / `"100"` |

说明：

- 以远端 FTP `SIZE` 为准计算百分比；跨过 10% 门槛才上报，避免刷屏。
- 收齐文件时会补报 `100`（若尚未报过）。

## 5. 注意事项

1. **数值多为字符串**：测点用 `"228.4"` 这类字符串，不是 JSON Number（`DailyEnergy.kWh` 除外，为数值）。
2. **`Totol_Energy` 拼写**：历史字段名，勿改成 `Total_Energy`，否则破坏兼容。
3. **`device` 与 SN**：下行带 `device` 时必须匹配本机，否则不处理。
4. **电量历史采样**：默认每日 **00:00** 固定落点（`ENERGY_HISTORY_DAILY_SCHEDULE=1`）；与 MQTT 周期无关。
5. 主题、Broker 等以 NVS / 工程宏为准；仓库默认多为占位值，部署请自行替换。
6. **应答区分**：远程控制回 `Control_ACK`（`params.ack=ok`）；召唤历史回 `GetData_ACK`（`ack=ok` + `DailyEnergy`）；FTP 升级受理回 `FtpOTA_ACK`（`params.ack=OK`）；下载进度回 `FtpOTA_Status`（每 10%）。
