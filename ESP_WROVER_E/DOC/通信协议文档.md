# MQTT / JSON 通信协议

> 依据当前固件实现（`components/APP/WIFI_STA/json.c`、`mqtt.c`）整理。
> 载荷为 **UTF-8 JSON**，字段名大小写敏感。

---

## 1. 传输说明

| 项                   | 说明                                                            |
| -------------------- | --------------------------------------------------------------- |
| 传输                 | MQTT                                                            |
| 上行主题（设备→云） | NVS`mqttpub`（默认 `device/pub`，网页 `/wsconfig` 可改）  |
| 下行主题（云→设备） | NVS`mqttsub`（默认 `device/sub`，网页 `/wsconfig` 可改）  |
| QoS                  | 订阅 QoS=1；发布按 MQTT 客户端配置                              |
| 周期上报             | 连接成功后约每`MQTTUBLISHED`（默认 15s）上报一次 `MeterAll` |
| 设备标识             | 本机 SN（NVS`gate.sn`）；报文里用字段 **`device`**    |

### 下行处理流程

1. 解析 JSON
2. 若存在 `device`：须与本机 SN 一致，否则丢弃
3. 按 `Type` 查分发表；**缺少 `Type` 时默认按 `Control` 处理**
4. handler 成功且表项配置了 ack 时，自动回应对应应答包

当前已注册下行类型：

| Type        | 处理          | 成功后应答                         |
| ----------- | ------------- | ---------------------------------- |
| `Control` | 开关机 / 重启 | `CmdAck`（简易确认）             |
| `GetData` | 召唤数据      | `CmdAck`（附带 `DailyEnergy`） |

## 2. 通用报文骨架

推荐统一结构：

```json
{
  "Type": "XXX",
  "device": "设备SN",
  "params": {
    "...": "..."
  }
}
```

| 字段       | 方向   | 必填     | 说明                                      |
| ---------- | ------ | -------- | ----------------------------------------- |
| `Type`   | 双向   | 建议必填 | 消息类型；下行缺省时按`Control`         |
| `device` | 双向   | 建议必填 | 设备 SN；下行缺失时仍继续分发（仅打日志） |
| `params` | 视类型 | 多数必填 | 业务参数对象                              |

---

## 3. 上行（设备 → 云）

### 3.1 状态变更 / 上线 — `StatusChange`

设备上线、状态变化时主动上报（如 `设备上线`）。

```json
{
  "Type": "StatusChange",
  "device": "CTR",
  "params": {
    "ctrlacl": "设备上线",
    "time": "2026-09-02 22:44:57"
  }
}
```

| 字段               | 说明                            |
| ------------------ | ------------------------------- |
| `params.ctrlacl` | 状态描述字符串                  |
| `params.time`    | 本地时间`YYYY-MM-DD HH:MM:SS` |

---

### 3.2 电表/传感器快照 — `MeterAll`

周期上报。测点值为字符串；**无效/未就绪字段可能省略**（如温度无效、电表某量为 0）。

```json
{
  "Type": "MeterAll",
  "device": "CTR",
  "params": {
    "headid": "2",
    "temperature": "27.40",
    "humidity": "39.00",
    "VolageA": "228.4",
    "CurrentA": "1.012",
    "PowerPA": "174.6",
    "Frequency": "49.96",
    "Totol_Energy": "635.72",
    "time": "2026-09-02 22:35:52",
    "PowerPeak_3min": "185.5",
    "PowerPeak_1h": "214.3",
    "PowerPeak_1d": "214.3",
    "PowerPeak_7d": "374.9",
    "PowerPeak_1m": "386.0"
  }
}
```

| 字段               | 单位/含义 | 备注                           |
| ------------------ | --------- | ------------------------------ |
| `headid`         | 上报序号  | 设备侧自增计数转字符串         |
| `temperature`    | ℃        | 无效（约 -200）时不上报        |
| `humidity`       | %RH       | `<0` 时不上报                |
| `VolageA`        | V         | A 相电压                       |
| `CurrentA`       | A         | A 相电流                       |
| `PowerPA`        | W         | 有功功率                       |
| `Frequency`      | Hz        | 电网频率                       |
| `Totol_Energy`   | kWh       | 累计电能（字段名沿用历史拼写） |
| `time`           | 本地时间  | `YYYY-MM-DD HH:MM:SS`        |
| `PowerPeak_3min` | W         | 约 3 分钟窗口峰值              |
| `PowerPeak_1h`   | W         | 约 1 小时窗口峰值              |
| `PowerPeak_1d`   | W         | 1 天窗口峰值                   |
| `PowerPeak_7d`   | W         | 7 天窗口峰值                   |
| `PowerPeak_1m`   | W         | 1 月窗口峰值                   |

> 区间电量历史 **不在** `MeterAll` 中上报，需通过下行 `GetData` 召唤。

---

### 3.3 控制应答 — `CmdAck`（对应 `Control`）

`Control` 执行成功后回：

```json
{
  "Type": "CmdAck",
  "device": "CTR",
  "params": {
    "ack": "CmdAck"
  }
}
```

---

### 3.4 召唤应答 — `CmdAck`（对应 `GetData` / MeterHistory）

召唤电量历史成功后回（`Type` 仍为 `CmdAck`，历史数据在 `params.DailyEnergy`）：

```json
{
  "Type": "CmdAck",
  "device": "CTR",
  "params": {
    "DailyEnergy": [
      {
        "date_1": "2026-09-01 00:00",
        "kWh": 1.234
      },
      {
        "date_2": "2026-09-02 00:00",
        "kWh": 0.856
      }
    ]
  }
}
```

| 字段            | 说明                                            |
| --------------- | ----------------------------------------------- |
| `DailyEnergy` | 区间用电数组，最多约 30 条（环形缓冲）          |
| `date_N`      | 该槽采样时刻`YYYY-MM-DD HH:MM`（N 从 1 递增） |
| `kWh`         | 该区间用电量（kWh，约 3 位小数）                |

无历史数据时，`DailyEnergy` 可能缺失（空历史不追加字段）。

## 4. 下行（云 → 设备）

### 4.1 远控电脑开关机 / 远程复位 — `Control`

`open` / `close` 驱动 **PWM 舵机** 按电脑机箱电源键（不是继电器断电）。`reboot` 重启的是 ESP32 本机。

```json
{
  "Type": "Control",
  "device": "CTR",
  "params": {
    "cmd": "open"
  }
}
```

| `params.cmd` | 含义                  | 执行                                                    |
| -------------- | --------------------- | ------------------------------------------------------- |
| `open`       | 电脑开机              | 舵机按下约 1s 后回位，并上行`开机执行` / `开机完成` |
| `close`      | 电脑关机（松键/回位） | 舵机回到松开位                                          |
| `reboot`     | 远程复位本设备        | `esp_restart()`                                       |

成功后设备回 **3.3** 的 `CmdAck`。

---

### 4.2 召唤电量历史 — `GetData`

```json
{
  "Type": "GetData",
  "device": "CTR",
  "params": {
    "get": "MeterHistory"
  }
}
```

| `params.get`   | 含义             |
| ---------------- | ---------------- |
| `MeterHistory` | 召唤区间电量历史 |

成功后设备回 **3.4** 的 `CmdAck`（含 `DailyEnergy`）。

---

## 5. 消息一览

| 场景          | 方向 | Type             | 要点                                                       |
| ------------- | ---- | ---------------- | ---------------------------------------------------------- |
| 上报登录/状态 | 上行 | `StatusChange` | `params.ctrlacl` + `time`                              |
| 上报电表信息  | 上行 | `MeterAll`     | 周期快照，字段在`params`                                 |
| 远控电脑开机  | 下行 | `Control`      | `cmd=open` → 舵机按电源键，回 `CmdAck`                |
| 远控电脑关机  | 下行 | `Control`      | `cmd=close` → 舵机回位，回 `CmdAck`                   |
| 远程复位本机  | 下行 | `Control`      | `cmd=reboot` → ESP32 重启，回 `CmdAck`                |
| 召唤电量历史  | 下行 | `GetData`      | `get=MeterHistory` → 回带 `DailyEnergy` 的 `CmdAck` |

## 7. 注意事项

1. **数值多为字符串**：测点用 `"228.4"` 这类字符串，不是 JSON Number（`DailyEnergy.kWh` 除外，为数值）。
2. **`Totol_Energy` 拼写**：历史字段名，协议勿随意改成 `Total_Energy`，否则破坏兼容。
3. **`device` 与 SN**：下行带 `device` 时必须匹配本机，否则不处理。
4. **电量历史采样**：默认每日 **00:00（24:00）** 固定落点（`ENERGY_HISTORY_DAILY_SCHEDULE=1`）；与 MQTT 周期无关，无 Shell/NVS 时刻参数。
5. 主题、Broker 等连接参数以 NVS / 工程宏为准。仓库默认是占位值，部署请自行替换。
